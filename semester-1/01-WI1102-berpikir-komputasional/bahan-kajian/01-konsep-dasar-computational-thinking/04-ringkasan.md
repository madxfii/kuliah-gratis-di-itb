## Apa yang Sudah Anda Pelajari

Di modul ini, Anda telah melalui perjalanan untuk memahami **Computational Thinking** — cara berpikir yang akan mengubah bagaimana Anda memecahkan masalah dalam hidup dan karir.

### Sub-Modul 1.1: Definisi & Konteks CT
✓ **CT adalah cara berpikir sistematis** untuk memecahkan masalah dengan logika yang jelas
✓ **CT bukan hanya untuk programmer** — setiap orang dan profesi bisa menggunakannya
✓ **CT ≠ CS ≠ Programming** — tiga konsep berbeda yang related:
  - **CT**: Cara berpikir (mindset)
  - **CS**: Disiplin ilmu tentang computation
  - **Programming**: Keterampilan teknis menulis kode
✓ **CT semakin penting** di era digital, di pendidikan, industri, dan kehidupan sehari-hari

### Sub-Modul 1.2: Empat Pilar CT
✓ **Dekomposisi** = Pecah masalah besar menjadi sub-masalah yang lebih kecil
✓ **Pengenalan Pola** = Identifikasi kesamaan, keteraturan, dan struktur yang berulang
✓ **Abstraksi** = Fokus pada informasi penting, abaikan detail yang tidak relevan
✓ **Desain Algoritma** = Merancang langkah-langkah terstruktur untuk menyelesaikan masalah

✓ **Keempat pilar saling melengkapi** — gunakan bersama-sama untuk solve masalah kompleks

### Sub-Modul 1.3: CT dalam Praktik
✓ **CT adalah universal** — bisa diapply ke berbagai domain (tech, healthcare, business, education, dll)
✓ **Studi kasus real-world** menunjukkan bagaimana profesional menggunakan CT setiap hari
✓ **CT + Domain Knowledge = Powerful** — kombinasi cara berpikir + pengetahuan spesifik

## Poin-Poin Kunci (Quick Review)

### Pilar 1: Dekomposisi
```
Gunakan ketika:
→ Masalah terasa besar dan overwhelming
→ Banyak aspek berbeda yang perlu dipertimbangkan
→ Tidak tahu dari mana harus mulai

Cara:
1. Identifikasi sub-problems / komponen utama
2. Pecah setiap sub-problem lebih lanjut jika perlu
3. Urutkan logis (mana yang harus dikerjakan dulu)
```

### Pilar 2: Pengenalan Pola
```
Gunakan ketika:
→ Ada data historis atau contoh-contoh
→ Anda ingin memprediksi atau mengoptimalkan
→ Ada struktur atau keteraturan yang bisa dimanfaatkan

Cara:
1. Kumpulkan data / contoh-contoh
2. Analisis untuk cari kesamaan atau perbedaan
3. Formulasikan pola / rule yang bisa di-generalize
4. Apply pola untuk predict atau solve masalah baru
```

### Pilar 3: Abstraksi
```
Gunakan ketika:
→ Ada detail yang membingungkan atau tidak relevan
→ Ingin fokus pada "big picture"
→ Ada kompleksitas yang bisa disederhanakan

Cara:
1. Identifikasi informasi yang PENTING untuk solve masalah
2. Identifikasi detail yang bisa diabaikan
3. Create simplified model atau representation
4. Use simplified model untuk communicate atau solve
```

### Pilar 4: Desain Algoritma
```
Gunakan ketika:
→ Ada langkah-langkah yang perlu diikuti
→ Ingin proses yang efisien dan repeatable
→ Ada banyak data atau iterasi yang perlu dikelola

Cara:
1. Tentukan input dan output
2. Desain langkah-langkah (step-by-step)
3. Pastikan urutan logis
4. Test dengan contoh (trace through)
5. Optimize jika perlu (lebih cepat, lebih clear, dll)
```

## Contoh Aplikasi Quick Reference

| Problem | Dekomposisi | Pengenalan Pola | Abstraksi | Algoritma |
|---------|-------------|-----------------|-----------|-----------|
| **Mencari rute tercepat** | Break into: data collection, estimation, comparison | Morning traffic is heavy on main roads | Focus on distance & time, ignore scenery | Step-by-step route evaluation |
| **Organize foto liburan** | Gather → sort by date → categorize → create album | Phones auto-tag photos by location | Date & location metadata matter, not ISO settings | Structured folder organization process |
| **Belajar untuk ujian** | Break by chapter → review → practice → rest | Soal tipe tertentu sering keluar | Study high-importance concepts, skip trivia | Study plan dengan time allocation |
| **Design aplikasi** | UI → Logic → Testing → Deployment | Successful apps follow certain patterns | Focus on user needs, ignore implementation details | Code architecture & development phases |
